LEDGERGUARD - 10-DAY COMMIT HISTORY PLAN
========================================

Purpose
-------
This document divides the current LedgerGuard codebase into a recommended 10-day
series of commits. For each day it lists the exact files, why each file belongs
in that commit, a suggested verification step, and explicit git commands.

Writing this file does not create commits. No push is performed. The commands
below are recommendations for how the history could have been built day by day.

Safety rules applied to this document
-------------------------------------
1. This file contains file paths, commit messages, rationale, verification
   steps, and explicit git add commands only.
2. It does not contain environment file values, private keys, RSA PEM material,
   tokens, cookies, connection strings with credentials, or tenant data dumps.
3. Demo credentials are not repeated here; they are documented in README.md.
4. Never stage with broad wildcards or all-files flags. Every day uses explicit
   paths so secrets cannot be staged accidentally.
5. The repository .gitignore already excludes: .env, .env.* except .env.example,
   *.pem, *.key, node_modules/, dist/, and coverage/.
6. Before finishing, verify with `git status --short` and scan this file for
   secret-like patterns.

Excluded from the plan: node_modules/, dist/, coverage/, .env, *.pem, *.key,
and other generated or ignored artifacts.
